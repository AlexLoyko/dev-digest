## What Works

2026-06-22 — `var(--ok)` is the correct CSS token for green/success icon color (used for check marks, approved verdict, "reviewed" status). Do NOT use `var(--success)` or `var(--green)` — those don't exist. Confirmed across settings, verdict banner, and PR list constants. ref: client/src/app/repos/[repoId]/pulls/[number]/_components/VerdictBanner/constants.ts:1

2026-06-22 — `Button` from `@devdigest/ui` auto-replaces the `icon` prop with a spinning `RefreshCw` when `loading=true`. Adding `icon="RefreshCw"` explicitly on a loading button is redundant — the component handles it. The spin animation runs via `ddspin 1s linear infinite` on the icon element. ref: client/src/vendor/ui/primitives/Button.tsx:24

2026-06-17 — `SEV[sev].c` from `@devdigest/ui` returns a hex string (e.g. `#ef4444`), NOT a CSS variable. Appending `"22"` / `"55"` gives valid 8-digit hex with ~13%/33% alpha — safe for `background` and `border` derivation. Do NOT use this trick with `var(--crit)` / `var(--warn)` style tokens (those are CSS vars and will produce invalid values). ref: client/src/app/repos/[repoId]/pulls/styles.ts:50

2026-06-17 — Shared display components for PR list cells live in `client/src/components/`. Pure display, no fetching. Accept `value | null | undefined`, render `–` for absent data. Pattern: `({ cost }: { cost?: number | null }) => cost && cost > 0 ? "$X.XXX" : "–"`. ref: client/src/components/RunCostBadge/RunCostBadge.tsx:1

2026-06-17 — Lazy-enable TanStack Query by passing `undefined` instead of a boolean flag: `usePrReviews(anchorRect && totalFindings > 0 ? pr.id : undefined)`. When `prId` is `undefined`, `enabled: !!prId` is false — no fetch fires. Query enables automatically when the condition becomes truthy. No conditional hook call needed. ref: client/src/app/repos/[repoId]/pulls/_components/PRRow/PRRow.tsx:28

2026-06-17 — Store `DOMRect | null` as hover state instead of `boolean` for popovers — gives both the trigger signal AND the position for `position: fixed` placement in one state value. Pattern: `onMouseEnter={(e) => setAnchorRect(e.currentTarget.getBoundingClientRect())}`. ref: client/src/app/repos/[repoId]/pulls/_components/PRRow/PRRow.tsx:34

2026-06-17 — `createPortal(content, document.body)` escapes `overflow: hidden` containers. Use for any overlay/popover rendered inside a clipped container. ref: client/src/app/repos/[repoId]/pulls/_components/FindingsPopover/FindingsPopover.tsx:96

2026-06-29 — `createPortal(content, document.body)` in a `"use client"` component is safe without a `mounted` guard because Next.js App Router never SSR-renders Client Components — they hydrate in the browser only. The `mounted` guard pattern (`const [mounted, setMounted] = useState(false); useEffect(() => setMounted(true), [])`) is needed only for Server Components or pages with `ssr` enabled. ref: client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/BlastGraphLightbox.tsx:1

2026-08-28 — Inline-style-only components in this codebase (no CSS classes — everything is `style={}` from `styles.ts`) can still emulate `:hover`/`:focus-within` without touching `globals.css`: put `onMouseEnter`/`onMouseLeave` AND `onFocus`/`onBlur` on the same wrapper element. React's `onFocus`/`onBlur` behave like native `focusin`/`focusout` (they bubble), so a handler on a `<li>` fires when ANY descendant button gains/loses focus — no `onFocusCapture` or `relatedTarget` check needed. Used to reveal the reorder buttons on row hover or keyboard focus while keeping them real, always-tabbable elements (opacity-only toggle, never `display:none`, so Tab-reachability and the `aria-live` reorder announcement keep working). ref: client/src/components/context-picker/ContextPicker.tsx:203

## What Doesn't Work

2026-08-29 — Every existing spinner in this codebase (`Button.tsx`'s `loading` state, `FindingsTab`, `ReviewRunAccordion`, `AgentCard`, `SkillCard`) applies the spin via an inline `style={{ animation: "ddspin 1s linear infinite" }}` on the icon. This is NOT reduced-motion-safe: the global `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important } }` rule (`client/src/vendor/ui/styles.css:286-292`) reliably caps animations set via a CSS class (e.g. `.skeleton`), but an inline `animation:` declaration on the element itself does not reliably get overridden the same way once any other inline style is present. Don't copy this pattern into new code just because five existing components already do it — it's carried debt, not a template. ref: client/src/vendor/ui/primitives/Button.tsx:82

2026-08-28 — A `startsWith("/")`/`startsWith("http://")` allowlist for hardening a Markdown `a`-override link handler is incomplete — it rejects legitimate relative hrefs like `foo/bar.md` (no leading slash) that don't match any prefix. Use scheme extraction instead: `href.match(/^([a-z][a-z0-9+.-]*):/i)?.[1]` — `undefined` (no scheme = relative) or `http`/`https` is safe, any other captured scheme (`javascript:`, `data:`, etc.) renders inert. ref: client/src/vendor/ui/primitives/Markdown.tsx:31

2026-06-29 — `{count && <Component />}` renders the literal number `0` in the DOM when `count === 0` — React renders falsy numbers (0, -0, NaN) as text nodes. Always use `{count > 0 && <Component />}` for numeric guards. `{!!count && ...}` also works but is less readable. ref: client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/SummaryBar.tsx:1

2026-06-29 — A d3 force-simulation graph must be mounted/unmounted (not toggled via CSS `display:none`). When the container is hidden via CSS, `getBoundingClientRect()` returns 0 for width/height and the simulation places all nodes at the origin. Correct pattern: conditionally render the graph (`{graphOpen && <BlastGraph />}`) so it mounts with real dimensions. ref: client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/BlastGraph.tsx:1

2026-06-18 — Fixing `.js` extensions in `client/src/vendor/shared/index.ts` alone is NOT enough. The individual contract files also import each other with `.js` extensions (`eval-ci.ts`, `observability.ts`, `platform.ts`, `productionize.ts`, `review-api.ts`, `adapters.ts`). All 6 must be fixed in addition to the barrel. Grep: `from '\./.*\.js'` in `client/src/vendor/shared/` to find them all. ref: client/src/vendor/shared/contracts/eval-ci.ts:2

2026-06-18 — `client/src/vendor/shared/index.ts` used `.js` extensions on all re-exports (`export * from './contracts/findings.js'`). This is the TypeScript ESM convention for Node.js but Next.js/webpack cannot resolve it — "Module not found: Can't resolve './contracts/findings.js'". The bug was latent: `import type` is erased at compile time so webpack never resolved the module. It surfaced only when `Severity` was imported as a value. Fix: remove all `.js` extensions from the client barrel. ref: client/src/vendor/shared/index.ts:17

2026-06-18 — `SeverityChip` with "N dots total" (render exactly N circles) is visually wrong — it gives no sense of scale. The correct model is always 12 slots: first `min(count, 12)` render as a single merged solid segment (height=2px), the remaining (12-N) render as faded separate dots. Width of merged segment = `N * SLOT_W + (N-1) * GAP`. ref: client/src/components/SeverityChip/SeverityChip.tsx:1

2026-06-17 — `Icon.AlertCircle` does not exist in `@devdigest/ui` — runtime error "Element type is invalid: expected a string... but got undefined". Never guess icon names; check existing usages (`grep -oh "Icon\.[A-Za-z]*"`) to find what's available. ref: client/src/app/repos/[repoId]/pulls/_components/FindingsPopover/FindingsPopover.tsx:56

## Codebase Patterns

2026-08-28 — "Derive, don't store" applies to list-selection state too: instead of `useState` + a sync `useEffect` to keep a "selected row" pointing at a valid item after filtering, store only the user's *override* (`manualPath: string | null`) and derive the effective selection as `manualPath && filtered.some(d => d.path === manualPath) ? manualPath : filtered[0]?.path ?? null`. When a filter narrows the list past the previous selection, the derived value self-corrects to the new first row with zero extra renders or effects. ref: client/src/app/repos/[repoId]/context/_components/ProjectContextView/ProjectContextView.tsx:38

2026-08-28 — When one component (`ContextPicker`) is mounted from two feature pages that each own a duplicate message sub-namespace with identical key names (`agents.json`'s `context.*` and `skills.json`'s `context.*` — skills has 2 extra keys agents lacks: `serializesAs`, `inheritNote`), give the component a `namespace: "agents" | "skills"` prop and resolve its own-copy strings via `useTranslations(\`${namespace}.context\`)`. Separately call `useTranslations("context")` (the standalone `context.json` file) for document-catalog strings — `sourceRoot.*`, `threat.*`, `tokens`, `tokensApprox`, `filter.showing` — which are NOT duplicated per page and only live there. There are three distinct "context" namespaces in this catalogue (`agents.context`, `skills.context`, top-level `context`); don't assume the word alone identifies one. ref: client/src/components/context-picker/ContextPicker.tsx:48

2026-08-28 — A reorderable/attachable document list keyed on `path` must not derive its display rows via `attachedPaths.map(p => documents.find(d => d.path === p)).filter(Boolean)` — that silently drops any attached path whose file was deleted from the repo after being attached, which is exactly the case a "missing in repo" badge exists to surface. Synthesize a stub row (`{ path, doc: null }`) for attached paths absent from the document catalog instead, and let downstream rendering treat `doc === null` as "render the row from the path alone, badge it as missing, skip any field that needs `doc`". ref: client/src/components/context-picker/helpers.ts:24

2026-08-28 — In `ContextPicker`'s row (`display:flex`, children `dragHandle | checkbox | rowGroup(flex:1) | chipRow(natural width)`), `chipRow`'s own total content width determines where it starts, because `rowGroup`'s `flex: 1` absorbs whatever space `chipRow` doesn't need — so any element whose presence/absence varies `chipRow`'s width (present on some rows, absent on others) shifts the shared `sourceRootLabel`/`tokenCount` column left or right across rows, even though those two spans have their own fixed `8ch`/`7ch` widths. The earlier fix reserved an always-present, fixed-width empty slot inside `chipRow` for that purpose; removing the up/down reorder buttons made that slot unnecessary rather than something to preserve — once nothing inside `chipRow` differs between attached and unattached rows, the column alignment holds without any reserved slot at all. Don't assume "there was a width-reservation hack here" means the hack is still needed after removing what it was reserving space for — check whether the asymmetry itself is gone first. ref: client/src/components/context-picker/styles.ts:24

2026-08-28 — `moveAttachedPath` (single-step neighbour swap, used for keyboard ArrowUp/ArrowDown) and drag-and-drop reordering are NOT the same operation — a drag can drop an item several positions away in one gesture, which a neighbour-swap primitive can't express without looping. Added a sibling pure function `reorderAttachedPath(attachedPaths, fromPath, toPath)` (splice-out/splice-in at the target's index, same `{paths, position, total}` return shape as `moveAttachedPath`'s `MoveResult`) rather than forcing drag-and-drop through the swap primitive or reinventing the shape inline in the component. Two distinct reorder primitives, same result type, each used by the interaction mode it actually fits. ref: client/src/components/context-picker/helpers.ts:126

2026-08-29 — Where a spinning icon needs to respect `prefers-reduced-motion` and the component's file isn't allowed to touch `styles.css`/`styles.ts`, use the Tailwind `className="animate-spin"` utility instead of an inline `style={{ animation: ... }}`. Tailwind v4 is already wired into this project (`@tailwindcss/postcss`, `@import "tailwindcss"` in `client/src/vendor/ui/styles.css:1`), so `animate-spin` compiles to a real stylesheet class (`animation: spin 1s linear infinite`), and the existing global `!important` reduced-motion rule (`client/src/vendor/ui/styles.css:286-292`) correctly caps it — same mechanism that already protects `.skeleton`. Zero new CSS or files needed; used for `BriefCard`'s "generating"/"updating" spinners (`Icon.RefreshCw size={... } className="animate-spin"`) instead of the codebase's usual `ddspin` inline-style pattern. ref: client/src/app/repos/[repoId]/pulls/[number]/_components/BriefCard/BriefCard.tsx:1

2026-08-29 — `BriefCard` has two independent "generation in flight" signals that must not be conflated: `useGenerateBrief().isPending` (the component's own mutation instance — the only thing that can ever produce a FIRST brief, since `useBrief` never auto-generates on a missing one) vs `data.stale` (a server-reported flag that drives `useBrief`'s own background-regeneration effect via a raw, separate `generateBrief()` call inside a `useEffect` — see `client/src/lib/hooks/brief.ts`). SPEC-02's EC-2 ties the with-earlier-brief dimmed/"updating" branch specifically to `data.stale`, not to `generate.isPending` — so clicking the regenerate `IconBtn` on an already-fresh, non-stale brief does NOT show the dimmed/updating treatment; that's by design, not a gap. ref: client/src/app/repos/[repoId]/pulls/[number]/_components/BriefCard/BriefCard.tsx:225

2026-08-29 — T21 (`BriefCard`'s two failure presentations, AC-16): given `apiFetch` can't actually deliver this route's `reason`/`hasPriorBrief` fields to the client (see the `What Doesn't Work` entry on `client/src/lib/api.ts:44`), the branch selector doesn't need those fields at all — "does a prior brief exist" is exactly `data.brief !== null` (the query cache's own current value), since a failed generation writes nothing (server contract) and so never changes it. `useBrief`'s own background-regeneration effect deliberately swallows its own failures with no card-visible state (its `catch` block comment says so explicitly) — only THIS component's own `useGenerateBrief()` mutation's `isError`/`error` drive the failure branches, gated `!isGenerating` so a newer, actually-in-flight regeneration (background or manual) always wins over a stale error from an earlier failed attempt. The failure cause text is rendered as `error.message` verbatim (dynamic, unTranslated — same `error instanceof ApiError ? error.message : t(...)` convention already used in `page.tsx`/`ContextTab.tsx`/`AddRepoView.tsx`), not a fabricated reason-specific sentence, since `brief.json`'s `card.failure.*` deliberately has no "cause" key and the task's own gotcha forbade adding one. The no-prior branch's "no earlier brief exists" statement reuses the existing `card.noBrief.body` string (not a `card.failure.*` key, but already in the same file) rather than adding a new key. ref: client/src/app/repos/[repoId]/pulls/[number]/_components/BriefCard/BriefCard.tsx:373

2026-08-28 — Native HTML5 `draggable` works fine directly on a `<button>` element — no wrapper span needed. This is also the standard accessible "reorderable list" pattern (e.g. GOV.UK Design System's drag-and-drop list): a real `<button>` as the drag handle gets HTML5 DnD (`draggable`, `onDragStart`/`onDragEnd`) for mouse users AND keyboard operability (`onKeyDown`) for free, letting one element serve both interaction modes instead of a decorative `<span>` handle plus separate always-visible arrow buttons. `aria-pressed` (not the ARIA-1.1-deprecated `aria-grabbed`) doubles as the "picked up" state toggle since the button already reads naturally as a toggle ("press to grab, press again to drop"). A mouse-initiated drag (`onDragStart`) should clear any in-progress keyboard "grabbed" state (and vice versa isn't needed — starting a keyboard grab is a discrete keypress, not a drag) so the two interaction modes never fight over which one currently owns the reorder. ref: client/src/components/context-picker/ContextPicker.tsx:339

2026-08-28 — A plan's acceptance grep for banned control words (e.g. `grep -inE "onSave|upload|delete|Edit"` to prove "no edit/delete control exists") also matches those words inside your own code *comments* (e.g. a header comment saying "No create/edit/upload/delete control"), producing a false-positive failure against the literal gate command. Phrase such comments without the banned words (e.g. "no document mutation affordance of any kind") so an automated grep-based acceptance check actually passes clean. ref: client/src/app/repos/[repoId]/context/_components/ProjectContextView/ProjectContextView.tsx:3
